01 · Why now

The hard part is not another model. It is the seams.

Today the app assumes Phonon 31M is the only engine. Every new model would otherwise mean a new settings screen, a new voice picker and a new download path. The plan replaces those assumptions with data.

Design principles from §3 of the full plan.

Offline first

Models download once; generation never needs the network. Cloud cloning stays optional, one-time and clearly labelled.

The model is data

A signed manifest describes files, languages, voices, capabilities and hardware. Adding a compatible model is registry work, not UI work.

Capabilities, not brands

The UI asks “does this model support cloning?” instead of “is this Kokoro?”. Gating stays honest as the catalog grows.

02 · Shortlist

Thirty-five candidates, one honest score each.

Filter by quality, Arabic support, runtime, license or capability. Select any model to add it to the implementation prompt. Fit badges react to the hardware profile below.

Scores are editorial (1–10) and anchored on public benchmarks — re-verify at pin time.

35 models

Click a card to toggle it for the prompt. “Fit” is calculated from the hardware profile in the next section. License and size figures must be re-verified against pinned manifests before shipping.

How the ★ score works: naturalness and prosody 40% · cloning and expression 25% · language coverage and depth 20% · efficiency and deployability 15%. 10 = best open-weight quality in its language pair; 9 = near state of the art; 8 = excellent default; 7 = good with trade-offs; 6 = competent but superseded; 5 = niche or experimental. Anchored on Artificial Analysis TTS Elo, vendor WER/CER and speaker-similarity tables, and public demos — re-check at pin time.

05 · Language coverage

Breadth without pretending every voice is equal.

Language chips come from each model’s declared coverage. Thin languages are shown with a quality note rather than hidden — a single French voice is still useful, as long as the UI says so. 13 of the 35 models speak Arabic; the rest must never show an Arabic chip.

Per-model language lists from §5 of the full plan.

06 · Roadmap

Ship the cheap win first, then earn the heavy ones.

Phase 1 is usable in under two weeks because it reuses the existing runtime. The 30–646-language flagships and the 8B+ heavyweights wait until the registry, licensing and hardware gates have proven themselves.

Tick phases to include them in the generated prompt.

Runtime 01

phonon-tts worker

WASM + WebGPU. Phonon 31M and the 40M family. Already in the app; only the URLs and manifest become dynamic.

Runtime 02

ONNX Runtime Web

WASM / WebGPU worker for Kokoro, Piper, MeloTTS, MMS, Supertonic 3, Kitten and Sopro. Small models, huge language reach, no installer growth.

Runtime 03

Local sidecar

Loopback-only process for Chatterbox, CosyVoice2, SILMA, Qwen3, VoxCPM2, MOSS, OmniVoice, FireRed, Breeze and the rest. Optional download, on-demand start, killed on quit.

07 · Naming

The rename is done. Voxarium is the product.

“Voxarium” is model-agnostic and no longer tied to one family. Phonon stays the flagship engine name. Select a name to see it in the generated prompt; the others are kept as the evaluation record.

Applied: product name, app id com.voxarium.app, installer, shortcuts and docs.

A rename is a migration, not a rebrand: userData, installer id, shortcuts, docs and the model registry all carry the name. Existing profiles are adopted from %APPDATA%\Phonon Studio on first launch.
