# Voxarium — Milestone 1 plan: public launch

**Status:** Proposal · **Date:** 1 November 2026
**Decisions already made:** the app is AGPL-3.0 with a CLA and stays open source forever; the install pipeline follows the one-contract design described in `docs/model-support.md`; targets are Windows, Linux and macOS; releases are built by GitHub Actions; the launch is announced on x.com.

> Not legal advice. Items marked **(verify)** are general knowledge or unchecked and must be confirmed when implemented.

---

## 1. Goal and definition of done

**Goal:** a public repo and a downloadable app on three platforms that does what the post says, with honest labels for what is and isn't verified.

M1 is done when all of these are true:

- [ ] `LICENSE` (AGPL-3.0), CLA bot, `NOTICE`/third-party notices, and `package.json` agree with each other.
- [ ] Tagging `v0.1.0` produces GitHub Release assets for Windows, Linux and macOS, with checksums and build provenance, without manual steps.
- [ ] On each OS a fresh user can install the app, pick **Phonon 31M**, and synthesize speech with no other setup.
- [ ] On Windows, at least **Kokoro and Supertonic 3** install and synthesize through the sidecar (already proven in the repo). On Linux and macOS the sidecar models are labelled by tier (section 5).
- [ ] The install flow runs the same seven stages for every model and ends with a **test synthesis** before a model is called "Ready".
- [ ] README, screenshots, install instructions, and the post assets exist and match reality.

Version: use **0.1.0**, not 1.0.0 (the current `package.json`). An honest "public beta" is easier to defend than a 1.0 with 13 sidecar models only resolve-checked.

## 3. Workstreams

Effort: **S** ≤ half a day · **M** 1–3 days · **L** a week or more. Streams A–C can run in parallel.

### A. Licensing and governance (do first, mostly S)

1. Add `LICENSE` (AGPL-3.0 full text); set `"license": "AGPL-3.0-or-later"`; add SPDX headers to source files **(S)**.
2. **CLA, not DCO.** A DCO only certifies origin under the project license; it gives no right to relicense or dual-license. Use a CLA modelled on the Apache ICLA/Harmony template, reviewed by a lawyer **(M)**.
   - Because voxarium.com does not exist yet, the CLA should name **you personally** as the licensee, with the right to assign to a successor company. Otherwise the first contributors grant rights to nobody.
   - Enforce with `contributor-assistant/github-action` (signatures stored in a branch or a separate repo) **(verify)**. Block merges until signed.
3. Third-party notices: generate at build time (e.g. `license-checker`) and bundle. AGPL-3.0 can include Apache-2.0, MIT and (L)GPL-3 code; confirm `phonon-tts` and the voice dataset licenses, and check `@breezystack/lamejs` **(verify)**.
4. AGPL §13: add a visible **Source code** link and version/commit in Settings → About. The local API is loopback-only, but this keeps modified builds compliant.
5. Repo files: `README`, `CONTRIBUTING` (CLA, how to add a model), `CODE_OF_CONDUCT`, `SECURITY.md` (the app runs downloaded code and a local API), `.github/ISSUE_TEMPLATE` including a **Model request** form (license, size, languages, ONNX/GGUF availability), PR template **(S)**.
6. Name check: trademark and domain search for "Voxarium" before posting **(S)**. Keep "unofficial, not affiliated with Gradium" wherever Phonon appears.
7. Store policy: do **not** plan Mac App Store or Microsoft Store in M1. Their terms conflict with AGPL-style distribution **(verify)**; GitHub Releases is the channel.

### B. CI and release pipeline (M)

**`ci.yml`** on PRs and pushes, matrix `ubuntu-latest`, `windows-latest`, `macos-latest`:
`npm ci` → `npm run icon` → `typecheck` → `build` → `npm test` (model-layer unit tests). Linux runs the Electron smoke test under `xvfb`; Windows runs the full `test:e2e`.

**`release.yml`** on tag `v*`, matrix per OS:

| OS | Artifacts | Notes |
| --- | --- | --- |
| Windows x64 | NSIS installer, portable `.zip` | Unsigned in M1 unless signing is ready (see below) |
| Linux x64 | AppImage, `.deb` | Needs FUSE for AppImage; document it. arm64 later |
| macOS arm64 + x64 | `.dmg`, `.zip` | Separate builds or universal **(verify)**; runner labels change, check at implementation |

Release job: collect artifacts → `SHA256SUMS` → **build provenance attestation** (`actions/attest-build-provenance`) → SBOM → draft GitHub Release with generated notes. Publish by hand after a smoke test. Leave auto-update (`electron-updater`) for M2: it needs signing on macOS.

**Signing (decide before launch; build the pipeline to work without it):**

- **macOS:** unsigned builds are blocked by Gatekeeper ("damaged" / "unidentified developer"). Signing and notarizing needs a paid Apple Developer account **(verify price)**. Without it, document the right-click → Open / `xattr` workaround and mark the macOS build "experimental".
- **Windows:** unsigned installers trigger SmartScreen. Options: SignPath Foundation (free for OSS, requires application) or Azure Trusted Signing **(verify eligibility for both)**. M1 can ship unsigned with a clear note.
- **Linux:** no signing needed; checksums plus provenance are enough.

### C. Cross-platform runtime (L)

1. **Platform-aware pack catalog.** Replace the single `platform: win32/x64` per pack with per-platform archives: `uv` and python-build-standalone for `win32-x64`, `linux-x64`, `linux-arm64`, `darwin-x64`, `darwin-arm64`, each with pinned size and SHA-256 **(M)**.
2. **Platform helpers:** one function for the venv python path (`Scripts/python.exe` vs `bin/python`), guard `msvc-runtime` and DLL setup to Windows **(S)**.
3. **Recipes with platform markers** (e.g. `msvc-runtime; sys_platform == "win32"`) and a per-recipe `platforms` list. A recipe that can't resolve on an OS is marked unsupported there, never attempted **(M)**.
4. **PyTorch variants:** Linux reuses the CUDA/CPU logic; macOS uses the default wheel; adapters learn `mps` with a CPU fallback for ops it lacks **(M)**.
5. **Hardware probe:** Apple Silicon (unified memory as VRAM), Linux GPU via `nvidia-smi`; AMD/Intel noted as CPU **(S)**.
6. **UI shell:** macOS title bar and menu, `CmdOrCtrl` shortcuts, `activate` handling, Linux tray/autostart or a clean off-switch **(M)**.
7. **Tests:** run the model-layer tests on all three OSes; add one **sidecar smoke test** (Kokoro and Supertonic, CPU, tiny sentence) per OS in a scheduled workflow, not on every PR **(M)**.

### D. The one-contract install pipeline (M–L)

Implement the seven stages as a first-class object so every model, route and OS goes through the same code:

`preflight → consent → toolchain → environment → weights (+aux) → prepare → verify`

1. **`electron/models/pipeline.cjs`:** builds an `InstallPlan` for (model, platform, route). Each stage reports `pending | running | done | skipped | failed` through the existing progress events, so the UI shows one consistent stepper **(M)**.
2. **Persisted state** in `install-state.json` (stage, error, timestamps) so a failed install can **resume or repair** from the failing stage **(M)**.
3. **Preflight that blocks:** one result with `blockers`, `warnings` and `totalBytes` (runtime + environment + weights + aux): disk on the right volume, RAM/VRAM, driver vs CUDA wheel, platform support, token for gated models **(M)**.
4. **Verify = golden synthesis:** synthesize a fixed sentence; check sample rate, duration and non-silence. A model is **Ready** only if this passes. Works for both Phonon (worker) and sidecar (`/synthesize`) **(M)**.
5. **Pin auxiliary assets (P0 from the report):** SILMA (Vocos, tashkeel), IndexTTS2 (4 helpers), MOSS (audio tokenizer) download unhashed on first start. For M1 either pin them or label those three models "first start needs network, unverified bytes" **(L; can defer to M2)**.
6. **Manifest schema additions:** `routes[]` (which of phonon / onnx-web / sidecar), `platforms[]`, `attribution`, `terms[]` (acceptable-use acceptance), `license.kind` (`permissive | conditions | nc | review`), `aux[]` (pinned) **(M)**.
7. **Community vs commercial registry flag:** add `commercial: true/false` use in the build and a CI check that fails if a non-commercial model is marked for a future commercial registry **(S, cheap now)**.
8. **Gated models:** guided flow (open model page → user accepts → token → access check → continue) **(M)**.

### E. Launch assets and the x.com post (S–M)

1. **Honest support table** in README: model × OS × tier (section 5).
2. **README rewrite:** what it is, 60-second quickstart per OS, the table, the privacy statement, the API example, licensing (AGPL, CLA), roadmap. Remove "Windows only" claims once true.
3. **Assets:**
   - 30–45 s screen recording: first-run chooser → install a model → synthesize → call the local API.
   - 2–3 screenshots (existing ones in `docs/screenshots`; refresh after UI changes).
   - Repo social preview image (1280×640).
4. **Repo setup:** topics (`tts`, `text-to-speech`, `electron`, `local-first`, `offline`, `ai`), Discussions on, 5–10 `good first issue` labels (e.g. "add model X", "translate UI", "test on distro Y").
5. **Claims to avoid** unless true on launch day: "works on macOS/Linux" without the tier, "15 models verified", "no telemetry" (audit network calls first; the report's table lists every outbound connection).

## 7. Risks

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Sidecar fails on Linux/macOS for many models | Bad first impressions | Tier labels, platform gating, smoke tests, launch with Phonon + Kokoro/Supertonic |
| Unsigned macOS / Windows builds | Scary warnings, drop-off | Signing decision before launch; clear install notes otherwise |
| CLA wording or entity mismatch | Can't relicense later | Lawyer review; name the individual with assignment rights |
| AGPL scares off some contributors | Fewer PRs | Explain why in CONTRIBUTING; the CLA is the cost of dual-licensing |
| A model license is misread | Legal exposure | Keep the acknowledgment gate; add `license.kind`; read the file at each pin |
| Overclaiming on x.com | Credibility | Post only the verified table |
| Name conflict ("Voxarium") | Rebrand after launch | Trademark and domain check now |
